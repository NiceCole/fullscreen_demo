# 班组 APP 首页 Demo 实施说明

## 1. 实现范围

本次仅实现一个用于演示的移动端首页 Demo，满足以下目标：

- 首页使用 Flutter 原生开发
- 详情页使用本地 H5 页面承载
- 不依赖后端接口
- 可用于后续 iOS 真机预演示
- 适配手机、折叠手机、平板

## 2. 为什么继续选择 Flutter

结合当前项目诉求，Flutter 比 uni-app 更合适，原因如下：

### 2.1 当前需求更看重首屏速度

这次最核心的要求不是“多端最快开发”，而是“首页首屏加载要做到最优”。  
Flutter 首页采用原生渲染，首屏性能和滚动稳定性通常会优于基于 Web 技术栈的方案，更适合做展示型首页。

### 2.2 iOS 真机演示更稳

如果需要在 iPhone 真机上预演示，Flutter 的视觉一致性、动画表现和复杂布局稳定性会更好，适合作为对外演示版本。

### 2.3 首页和详情页职责可以拆开

本方案不是让 Flutter 承担全部内容页面：

- 首页由 Flutter 负责，保证秒开体验
- 详情页由 H5 负责，保证后续内容迭代效率

这比纯 uni-app 或纯 H5 更贴合当前阶段。

## 3. Flutter 和 uni-app 的区别

### 3.1 Flutter

- 渲染方式：自绘 UI，偏原生体验
- 优势：性能更好、动画更稳、复杂页面一致性更强
- 成本：Flutter 开发门槛相对更高，前端团队需要适应 Dart

### 3.2 uni-app

- 渲染方式：更偏 Web 跨端思路
- 优势：前端团队上手快，多端复用效率高
- 成本：在高性能首页、复杂交互、长远体验稳定性上通常弱于 Flutter

### 3.3 本项目建议

如果项目当前目标是：

- 首页展示效果优先
- 首屏性能优先
- iOS 真机演示优先

建议选择 Flutter。

如果未来目标变成：

- 大量业务页面快速铺设
- 前端团队主导开发
- 小程序/H5/App 多端共享代码优先

则可以再评估 uni-app。

## 4. 当前 Demo 架构

```text
Flutter App
├─ 首页：Flutter 原生页面
└─ 详情：WebView 加载本地 H5
```

### 4.1 首页

参考设计稿首页结构，已包含：

- 顶部品牌区
- 公告通知条
- 9 宫格功能入口
- 待办任务列表
- 底部导航

### 4.2 详情页

详情页使用本地静态 HTML 文件，通过 Flutter WebView 打开。  
这样即使没有接口文档，也可以完整演示“首页进入详情”的流程。

## 5. 性能策略

为了尽量做到首屏最优，本次方案使用了以下策略：

1. 首页不使用 WebView
2. 首页静态 mock 数据本地内置
3. 详情页延迟加载
4. 页面结构保持轻量
5. 不依赖接口、不依赖首屏远程配置

## 6. 适配策略

首页根据屏幕宽度自动切换宫格列数：

- 手机小屏：2 列
- 大屏手机 / 折叠屏：3 列
- 小平板：4 列
- 大平板：5 列

同时处理了以下适配点：

- 安全区
- 横向边距
- 标题截断
- 卡片比例
- H5 响应式布局

## 8. 需要你后续在本机补齐的部分

由于当前执行环境没有可用的 Flutter CLI，我没法直接在这里运行 `flutter create` 或生成完整平台工程。  
因此如果你要真正上 iOS 真机，还需要在有 Flutter 环境的机器上补齐标准工程目录：

- `ios/`
- `android/`
- `.dart_tool/`
- `test/`

推荐方式：

1. 在该目录执行 `flutter create .`
2. 保留我已经写好的 `lib/`、`assets/`、`pubspec.yaml`、文档文件
3. 执行 `flutter pub get`
4. 在 macOS 上连接 iPhone 真机运行
